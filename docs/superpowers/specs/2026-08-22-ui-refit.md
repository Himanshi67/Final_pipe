# Final_pipe UI Refit — spec

Source: code audit of `gui.py`, `app.py`, `validate_csv.py` on 2026-08-22
(main @ abd6f5c).

The pipeline engine is solid; the leverage is in the human touchpoints — the
review step, catching bad data before it costs a validation round, and
publishing with legible feedback. Four phases, each independently shippable.

## Phase 1 — quick wins  ✅ SHIPPED (commits `3d03967`…`8697d2d`, plan, moved 2026-11-19: `_not_in_use/docs/superpowers/plans/2026-08-22-ui-quick-wins.md`)

1. **Inline price & URL sanity in review** — flag sale > MRP, price ≤ 0,
   below the batch's `--min-price`, and non-http(s) `url_link`, as a warning
   strip above the editor. Today these surface only at validation, two steps
   later. (`gui.py:426–472`)
2. **Search + brand filter above the review table** — status tabs are the only
   scope control; on a 300-SKU batch finding one row means scrolling a fixed
   420px window. (`gui.py:545–563`)
3. **Category as a dropdown** — `SelectboxColumn` fed from
   `app.CATEGORY_COMBOS` so every edit is already a legal snap target; free
   text can miss the exact-string snap and only fail at validation as
   `category_not_in_map`. (`gui.py:447–472`, `app.py:308–339`)
4. **Auto-validate at the end of the build** — step 3 runs
   `validate_csv.validate_export()` right after `process_inventory()` and
   shows the issue count inline; step 4 becomes a re-check. (`gui.py:653–706`)
5. **Batch summary after build** — avg images/SKU, zero-image rows,
   `_spec_gaps` rows, missing-brand count, price range, category
   distribution. (`gui.py:678–690`)

~~Render the enricher's `_report.md`~~ — already implemented at
`gui.py:359–362`; dropped from the plan.

## Phase 2 — the review step (the big lift)  ✅ SHIPPED (commits `b01968d`…`074ca60` + `d6db572`, plan, moved 2026-11-19: `_not_in_use/docs/superpowers/plans/2026-08-22-ui-review-cards.md`)

- **Card mode**: one SKU at a time — all scraped images as a gallery (today:
  one thumbnail), editable price pair, specs with `_spec_gaps` highlighted,
  source-link button, Approve / Needs link / Reject advancing to the next
  unreviewed SKU. Reuses `write_edits_back` (`gui.py:475–514`).
- **Image keep/drop per SKU**: drops recorded to a column in `_filled.xlsx`;
  `app.process_inventory()` skips them. Pre-check the validator's
  `image_not_a_product_photo` suspects.
- **Validation issues deep-link back to review**: issue row → step 2 filtered
  to that SKU.

## Phase 3 — run telemetry + publish legibility  ✅ SHIPPED (commits `038c2f7`…`805c42a`, plan, moved 2026-11-19: `_not_in_use/docs/superpowers/plans/2026-08-22-ui-telemetry-publish.md`)

## Phase 4 — bigger bets (each independent)  (plan, moved 2026-11-19: `_not_in_use/docs/superpowers/plans/2026-08-22-ui-run-manager.md`)

- **Run manager home**: list `runs\<name>\` with stage reached, row counts,
  resume / delete / archive-to-`batches\` (+ generated README).
- **Category map editor**: edit `category_map.xlsx` +
  `SubCategory_Attributes_Master.xlsx` in-app, warning when an edit orphans
  categories used by past batches.
- **SEO preview**: when the SEO checkbox is ticked, preview generated meta for
  5 sample rows before building. Stays opt-in.

## Constraints (all phases)

- No LLM calls anywhere; no new dependencies beyond what `.venv` already has.
- Scripts stay at repo root; `gui.py` keeps delegating to `sku_enricher.py` /
  `app.process_inventory()` — no pipeline logic in the GUI.
- Import gating on `status.startswith("FOUND")` untouched; two-pass statuses
  stay un-importable.
- SEO opt-in; publish keeps dry-run-first, two-gate commit.
- Politeness delays and cache semantics are not UI concerns.
