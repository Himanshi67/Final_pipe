Hosted pipeline on Render

Operator guide for the Linux container copy of the wizard (gui.py).

What the hosted copy is

The hosted copy runs the same 5-step wizard as the local machine. It runs in share mode.

  • A password gate shows first. Nothing else shows until the user gives the correct password.
  • Publish, delete, archive and taxonomy edits are off.
  • Each enrichment run has a search budget cap. GUI_SHARE_BUDGET sets the cap (default 50 serper credits).
  • The headless browser flags and --force are removed from every run.
  • The hosted copy has no WooCommerce credentials. It cannot write to the live store.

Cost

The service uses the Render Starter instance type and one 5 GB persistent disk. A persistent disk needs a paid instance type, so the free type does not work. Render bills the instance and the disk separately. Confirm the current prices on render.com/pricing before you apply the Blueprint.

Serper credits are a separate cost. The serper.dev account pays for them, not Render.

One-time setup

  1. Open the Render dashboard.
  2. Select New, then Blueprint.
  3. Connect the GitHub repository atavisticrystal6888/Final_pipe. Render reads render.yaml from the repository root.
  4. Enter a value for GUI_SHARE_PASSWORD. Use 12 characters or more. The gate refuses a shorter password and shows only an error.
  5. Enter the serper.dev API key in SERPER_API_KEY.
  6. Select Apply. Render builds the image, creates the disk and starts the service.
  7. Open the service URL. Give the password. Confirm that the share-mode banner shows.

The repository is public. Do not put a password or a key in render.yaml or in any file. Render asks for the two secrets only when you first apply the Blueprint. To change them later, use the service's Environment page.

How updates deploy

Push a commit to main. Render builds a new image from that commit and restarts the service.

A deploy stops a running enrichment. See "Known limits".

The disk mounts at /data. On each boot, docker-entrypoint.sh links each state folder in /app to the same folder on the disk.

To change the taxonomy for the hosted copy, edit the files on the local machine, commit them and push to main.

Known limits

  • Retailer sites can block data-centre IP addresses more often than a home connection. Expect more NOT FOUND - … blocked rows than on the local machine.
  • The image has no headless browser. The Playwright package is installed, but its browsers are not.
  • A redeploy or a restart stops a running enrichment. Start the run again from the wizard. It resumes from its last checkpoint.
  • Use one instance only. A Render disk attaches to one instance, so the service cannot scale out.
  • A clients/<slug>/.env file on the disk overrides the Render environment variables. Do not create one unless you need that override.

Run the image locally with Docker

Build the image from the repository root:

docker build -t final-pipe .

Run it with a local folder as the disk:

docker run --rm -p 10000:10000 ^
  -e GUI_SHARE_MODE=1 ^
  -e GUI_SHARE_PASSWORD=change-me-12chars ^
  -e SERPER_API_KEY=your-key ^
  -v "%CD%\docker-data:/data" ^
  final-pipe

The example uses Windows cmd line breaks (^). In PowerShell, use a backtick. In a POSIX shell, use a backslash and "$PWD/docker-data:/data".

Check the health endpoint:

curl http://localhost:10000/_stcore/health

The response is ok. Then open http://localhost:10000 in a browser.
